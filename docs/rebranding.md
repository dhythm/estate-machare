# Estate Machare — リブランディング設計

Agri Machare（農機具の売買・レンタル・運搬マッチング）を、同じ共通基盤のうえで
不動産（売買・賃貸）版へ作り替えた記録。machare は MAtCH + shARE、所有する人と
必要とする人をつなぐ基盤の名前で、扱う対象だけが入れ替わっている。

## ブランドの考え方

**不動産と、次の可能性を。**

物件を所有する人、必要とする人、仲介する人をつなぐ。購入・賃貸・買取オプションを
比較し、取引のやり取りから条件の登録までを同じ場所で進められるプラットフォーム。

トップのメッセージは「物件の可能性を、次の人へ。」。最初に目的を選んで検索でき、
説明を読み終える前に自分の用事を始められる。

## ドメインモデルの対応

| 農機具版                       | 不動産版                                     | 備考                                    |
| ------------------------------ | -------------------------------------------- | --------------------------------------- |
| `maker` メーカー               | `zoning` 用途地域                            | 住居系・商業系・工業系の8区分           |
| `condition` 状態               | `layout` 間取り                              | 1R〜4LDK以上。土地は持たない            |
| `hours` 稼働時間               | `floorArea` 専有面積（㎡）                   | 土地は敷地面積として使用                |
| `year` 年式                    | `builtYear` 築年                             | 土地は持たない                          |
| —                              | `nearestStation` / `walkMinutes`             | 最寄駅と駅徒歩分                        |
| —                              | `leaseType` 借家種別                         | 普通借家 / 定期借家。賃貸に対応する出品 |
| カテゴリ（トラクター ほか）    | マンション / 戸建 / 土地 / 事業用            |                                         |
| `seller.kind`（個人農家 ほか） | 個人 / 宅建業者 / 管理会社 / 法人            |                                         |
| `rentPerDay` 日額              | `rentPerMonth` 月額賃料                      |                                         |
| —                              | `depositMonths` / `keyMoneyMonths`           | 敷金・礼金は**月数**で保持し金額を導出  |
| `rentToOwn` レンタル購入       | `purchaseOption` 買取オプション              | 支払済み賃料を購入価格に充当            |
| `Rental` / `rentals`           | `Lease` / `leases`（`tenantUserId`）         | 日数 → 契約月数、初期費用を申込時に確定 |
| `TransportJob` 運搬案件        | `PropertyRequest` 物件リクエスト             | 探索方向を逆にした掲示板                |
| `CarrierProfile` 運搬者        | `AgentProfile` 担当者（`handledCategories`） | 対応地域 + 取扱カテゴリでマッチング     |
| 距離帯の運搬料金               | 初期費用の目安（`lib/lease.ts`）             | 前家賃 + 敷金 + 礼金 + 仲介手数料       |

敷金・礼金を月数で持つのは、日本の賃貸表記に一致し、月額賃料から金額を導出できて
二重管理が起きないため。運搬は「所有する人 / 必要とする人 / **仲介する人**」の3者
構成を保ったまま物件リクエストへ転用し、掲示板・提案・事業者プロフィール・地域
マッチング・状態機械・運営タブをすべて意味のある形で残した。

## 実装上の原則

- 認証・権限・API の形・データストアの契約は変えず、既存コンポーネントの情報階層と導線を保つ。
- 出品者、入居者、担当者は同一アカウントで行き来できる。固定した役割別アカウントへ分断しない。
- 検索の条件やログイン前の物件情報を、次の画面で失わない。
- スキーマは既存のマイグレーションを書き換えず、`0015`〜`0018` を追加して移行する。
- 変数名・関数名・DB 列名は英語で、ローマ字を避ける（`walk_minutes`、`key_money_months` など）。
- 未実装のエスクロー決済、メール通知、保証を実装済みとして案内しない。

## 現在のサービス範囲

元のサービスはコンセプト検証版で、実決済は未実装。今回も本番決済や重要事項説明、
電子契約、新規会員登録を追加していない。期間指定の賃貸借契約、出品条件に応じた
購入充当、取引メッセージ、物件リクエストのマッチングを実装済み機能として扱う。

## 画像制作

- 生成方法: この実行環境に画像生成ツールがないため、写真ではなく決定的な SVG で用意した。
- 配置: カテゴリ見本 `public/properties/{apartment,house,land,commercial}.svg`、
  ヒーロー `public/brand-city.svg`（1600×900、左三分の一を静かに保ち文字を重ねられる構図）。
- 参照箇所（`lib/server/listings.ts` の `imageByCategory`、`components/hero.tsx`、
  `app/login/page.tsx`）はパスだけを見ているため、写真が用意できたら同じパスで
  差し替えられる。

## 検証結果（2026-09-16）

- `pnpm check`: lint・整形・型・未使用コード検出・Vitest 417件すべて成功。行カバレッジ 93.7%。
- `pnpm test:pglite`: 同じ417件を PGlite で検証し成功（追加した `0015`〜`0018` を含む）。
- 物件属性・月額賃料・敷金礼金・買取オプション・物件リクエストの状態機械を単体テストで検証。
- 農機具由来の語・列・ファイル・URL が残っていないことを確認。
